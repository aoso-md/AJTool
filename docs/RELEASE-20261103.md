## Corrección del bloqueo de pruebas

El log íntegro de la ejecución local del3/11 contiene192pruebas PostgreSQL aprobadas y un fallo en postgres-tls.test.mjs: OpenSSL no estaba en PATH. El proceso Node22 sí se estaba usando; no era un fallo de migración ni autenticación productiva. La prueba genera una CA efímera exclusivamente para el PostgreSQL desechable.

Se añade detección de OpenSSL en PATH y en la instalación estándar de Git for Windows, con override AJTOOL_OPENSSL_BIN. El runner comprueba el requisito antes de iniciar contenedores o cientos de pruebas. La verificación TLS de la aplicación permanece obligatoria. Un requisito ausente o una suite desconocida/private termina con error, sin declarar un falso PASS.

```powershell
# Usar Node22 en el proceso principal y sus hijos; no instalar PostgreSQL global.
npx.cmd --yes node@22 db/test/run-postgres-tests.mjs --only=postgres-tls
# Sólo si OpenSSL no está instalado o no se encuentra automáticamente:
$env:AJTOOL_OPENSSL_BIN = 'C:\Program Files\Git\usr\bin\openssl.exe'
```

Linux CI usa Node22 y OpenSSL del runner. PostgreSQL CI prueba16y17 con Docker, bases/roles sintéticos y contenedores aleatorios etiquetados. No necesita secretos productivos. Comando completo en un checkout limpio con las dependencias backend instaladas:

```sh
node db/test/run-postgres-tests.mjs --postgres-major=16
node db/test/run-postgres-tests.mjs --postgres-major=17
```

La matriz CI y las suites normales siguen activas. Las evidencias del equipo se mantienen fuera del repositorio publicado; la evidencia de CI corresponde al SHA del PR.
